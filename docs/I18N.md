# 多语言（i18n）规范

> 本 mod 支持 18 种语言。技能名**不手写**，一律取原版官方翻译，保证与游戏内技能面板术语一致。

## 目录与文件分组

```
42.20/media/lua/shared/Translate/<语言代码>/
├─ ItemName.json      "Base.XpOrb_<技能>" × 35     物品名
├─ IG_UI.json         IGUI_ExperienceOrb_* × 5     界面文本
└─ ContextMenu.json   ContextMenu_ExperienceOrb_Use 右键菜单
```

语言代码与原版一致（`<游戏目录>/media/lua/shared/Translate` 下的文件夹名）：
`EN CN CH DE FR ES ES_MX ES_CL IT PT PTBR RU UA PL NL JP KO TR`，未提供的语言由引擎自动回退 EN。

> **键放在哪个文件不是随便放的。** 引擎 `Translator.getTextInternal` 按**键前缀**把查询路由到不同的表
> （`UI_` / `Moodles_` / `IGUI_` / `ContextMenu_` / `Sandbox_` / `Tooltip_` / `Attributes_` / …），
> 而每个表由同名文件装载（`tryFillMapFromFile` / `tryFillMapFromMods` 以文件名取内容）。
> 因此：物品名放 `ItemName.json`、`IGUI_*` 放 `IG_UI.json`、`ContextMenu_*` 放 `ContextMenu.json`。
>
> 键名大小写也要对：`IGUI_` 是全大写（早期写成 `IgUI_` 属于不合规，已修正）。

## 本 mod 用到的键

| 键 | 文件 | 用途 |
|---|---|---|
| `Base.XpOrb_<技能>` | `ItemName.json` | 35 个物品的本地化名称 |
| `IGUI_ExperienceOrb_OwnerName` | `IG_UI.json` | 球名归属格式，如 `%1(%2)` → `力量经验球(Shimakaze)` |
| `IGUI_ExperienceOrb_Gained` | `IG_UI.json` | 吸满提示，`%1` = 本次获得 XP |
| `IGUI_ExperienceOrb_Partial` | `IG_UI.json` | 部分吸收提示，`%1` = 获得，`%2` = 球内剩余 |
| `IGUI_ExperienceOrb_Capped` | `IG_UI.json` | 已满 10 级提示，`%1` = 球内剩余 |
| `IGUI_ExperienceOrb_Capacity` | `IG_UI.json` | `%1/%2` 剩余/容量（当前球名不再使用，保留备用） |
| `ContextMenu_ExperienceOrb_Use` | `ContextMenu.json` | 右键菜单项 |

## 编码约定（写错就会"服务器不认 / 乱码"）

原版实测 **UTF-8 无 BOM + LF**；Skill Recovery Journal 实测 **UTF-8 无 BOM + CRLF**——两者都能加载。
本 mod 统一 **UTF-8 无 BOM**，生成器会强制校验。以下都会出问题：

- **UTF-8 BOM**：首字节变成 `EF BB BF`，JSON 解析失败 → 所有键显示成原始文本（玩家看到 `Base.XpOrb_Strength`）；
- **UTF-16 / GBK**：解析失败或乱码；
- **`.lua` 源码里写非 ASCII**：LuaJ 抛 `ArrayIndexOutOfBoundsException`，整个文件作废（中文只允许出现在 JSON）；
- **PowerShell 脚本里写非 ASCII**：Windows PowerShell 5.1 会用系统 ANSI 代码页读取**无 BOM** 的 `.ps1`
  （实测把中文读成 `缁忛獙鐞?` 并直接语法报错）。因此 `tools/gen_translate.ps1` **保持纯 ASCII**，
  所有文案放在 `tools/translate_data.json`（UTF-8 无 BOM，脚本显式按 UTF-8 读取）。

## 生成 / 校验

```powershell
# 自动探测原版安装目录，重建 18 种语言并校验
powershell -NoProfile -ExecutionPolicy Bypass -File tools\gen_translate.ps1
# 显式指定原版目录
powershell -NoProfile -ExecutionPolicy Bypass -File tools\gen_translate.ps1 -VanillaRoot "G:\SteamLibrary\steamapps\common\ProjectZomboid"
```

脚本流程：读取原版 `Translate/<LANG>/IG_UI.json` 里的官方技能名（`IGUI_perks_*`，缺失按键回退 EN）→
套用 `tools/translate_data.json` 的格式串生成三个文件 → 校验（无 BOM、合法 UTF-8、JSON 可解析、35 键齐全）。

**技能 id 与原版键名的三处差异**（容易踩坑）：

| 本 mod / `Perks.<id>` | 官方翻译键 |
|---|---|
| `PlantScavenging` | `IGUI_perks_Foraging` |
| `Lightfoot` | `IGUI_perks_Lightfooted` |
| `Sneak` | `IGUI_perks_Sneaking` |

新增一种语言：在 `tools/translate_data.json` 的 `languages` 里加一行
（`item` / `use` / `owner` / `capacity` / `gained` / `partial` / `capped` 七个格式串，
`%1` = 官方技能名、`%2` = 角色名），重跑生成器即可。

## 球名与其它动态文本为什么在客户端拼

服务端调用 `item:setName()` 会把名字**固定成服务器语言的字符串**，中文客户端就会看到英文球名。
所以采用两层：

1. **生成时（服务端）** 写一次 `"<技能球>(<账号名>)"` —— 即使客户端没有运行本 mod 的客户端脚本，
   球名也是对的（只是语言跟随服务器）；
2. **客户端**（`ExperienceOrb_ClientName.lua`）用 `instanceItem(fullType)` 造一个全新实例取
   **干净的基础名**（原版 Lua 从不使用 `getText("Base.*")` 取物品名，所以不能从物品自身名字推导），
   按**本机语言**重拼一次；**与当前名字相同就跳过**（幂等），因此 `(用户名)` 不会被叠加两次。

> 踩坑记录：早期实现从"物品当前名字"取基础名，于是每扫一次就再包一层 →
> `体格经验球(Shimakaze)(Shimakaze)…`。现在基础名只可能来自"全新实例"或 fullType 字符串。

同理，吸收后的头顶提示由服务端回传**数值**（`sendServerCommand … "orbResult"`），
客户端用 `_Gained` / `_Partial` / `_Capped` 拼文本，才能保证提示也是玩家自己的语言。
